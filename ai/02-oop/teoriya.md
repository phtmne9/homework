## Задание 2. Структуры данных

**Что такое список в Python?** Упорядоченная изменяемая коллекция элементов,
доступ по индексу: `scores = [10, 12, 9]`.

**Чем список отличается от кортежа?** Список изменяемый, кортеж нет. Кортеж
быстрее, занимает меньше памяти и может быть ключом словаря, список — не может.

**Что такое словарь?** Коллекция пар «ключ — значение» с доступом по ключу
за constant time: `student = {"name": "Ali", "score": 10}`.

**Когда удобно использовать список словарей?** Когда нужна таблица: каждый
словарь — строка, ключи — колонки. Это естественная форма датасета до того,
как он попадёт в pandas.

**Что такое ключ и значение в словаре?** Ключ — уникальный неизменяемый
идентификатор, значение — связанные с ним данные. В `{"name": "Ali"}` ключ
`name`, значение `Ali`.

**Как добавить новый ключ в словарь?** Присваиванием: `student["average"] = 10.33`.

**Зачем в анализе текста используется lower()?** Чтобы регистр не мешал
сравнению: «Отлично» и «отлично» должны считаться одним словом.

**Как посчитать среднее значение по списку чисел?** `sum(scores) / len(scores)`,
предварительно проверив, что список не пустой.

**Как пройтись циклом по списку?** `for score in scores:`

**Как пройтись циклом по списку словарей?** `for student in students:` и внутри
обращаться по ключу — `student["name"]`.

## Задание 3. ООП

**Класс** — шаблон, описывающий структуру и поведение объектов.

**Объект** — конкретный экземпляр класса со своими данными.

**Атрибут объекта** — переменная, принадлежащая экземпляру: `self.positive_words`.

**Метод** — функция внутри класса, работающая с данными объекта.

**Зачем нужен self?** Это ссылка на конкретный экземпляр. Через неё метод
получает доступ к данным именно того объекта, у которого он вызван.

**Зачем нужен `__init__`?** Конструктор: вызывается при создании объекта и
задаёт начальное состояние.

**Инкапсуляция** — сокрытие внутреннего устройства за понятным интерфейсом.
Снаружи вызывают `analyze_text()`, не зная, как считается score.

**Наследование** — создание класса на основе существующего с переиспользованием
его поведения.

**Полиморфизм** — одинаковый вызов работает по-разному в зависимости от типа
объекта. Разные анализаторы могут иметь свой `analyze_text()`.

**Абстракция** — выделение существенного и отбрасывание деталей. «Анализатор
отзывов» как понятие важнее, чем конкретный способ подсчёта слов.

**Зачем ООП в AI-приложениях?** Модель, препроцессор и загрузчик данных — это
объекты с состоянием. ООП позволяет заменить одну модель другой, не переписывая
остальной код: достаточно сохранить интерфейс `fit`/`predict`.

## Задание 4. SOLID

**S — Single Responsibility.** У класса одна причина для изменения.
`ReviewAnalyzer` анализирует текст, но не читает файлы и не рисует графики.

**O — Open/Closed.** Класс открыт для расширения, закрыт для изменения.
Новые слова добавляются через `add_positive_word()`, а не правкой кода класса.

**L — Liskov Substitution.** Наследника можно подставить вместо родителя без
поломки программы. Если `SmartAnalyzer` наследует `ReviewAnalyzer`, его
`analyze_text()` обязан возвращать ту же структуру.

**I — Interface Segregation.** Лучше несколько узких интерфейсов, чем один
широкий. Классу, который только читает данные, не нужны методы обучения модели.

**D — Dependency Inversion.** Зависеть надо от абстракций, а не от конкретных
реализаций. Сервис должен принимать «любую модель с методом predict», а не
жёстко конкретный класс.
